Now Forget Everything

On a GPU, requests MUST share the chip. Batching is how GPUs stay efficient. The fix isn't isolation — it's observability.
Now forget everything. GPUs don't have cgroups. There are no per-request resource limits. Thirty-two requests share one chip at the same time. Isolation would work but it kills throughput — you'd use 10% of a $40,000 card. On GPU, the fix isn't isolation. It's observability. That's what this talk is about.

Two Phases of Every Reply

Every LLM response has two phases. Prefill reads what you sent — fast, once. Decode writes the reply one token at a time — slower, hundreds of times. TTFT is Time To First Token. ITL is Inter-Token Latency. Remember ITL — that's where the ghost lives.

TTFT: Did They Get a Seat?

TTFT
Time to First Token
TTFT = queue_time + prefill_time
< 200ms → User doesn't notice
> 2 seconds → User rage-clicks
TTFT is the delay before the first word appears. Under 200ms, invisible. Over 2 seconds, they've already hit refresh.

ITL: How the Seat Feels

ITL
Inter-Token Latency
ITL is THE noisy neighbour signal. It spikes when someone ELSE joins the batch.
ITL is the gap between each token during decode. 14ms feels instant. 45ms feels choppy. ITL spikes when someone else joins the batch. That's the noisy neighbour signal.

Why We Batch

One Request on a GPU

Eight Requests Batched

Batching turns memory-bound decode into compute-bound decode. That's why every LLM server does it.
A GPU running one request is 10% utilized. Batch eight together — 65%. Same card, eight times the work. This is why batching exists.

Lock the table until everyone finishes

Static batching locks four requests together. Short ones finish, sit idle. Everything waits for the longest. 65% wasted.

Continuous batching checks after every step. Slot opens? Fill it immediately. 36x throughput. But now every request shares every step. One long request sets the pace for everyone.

Taming Blake

1. Cap Batch Size

--max-num-seqs 16

Default is 256! Start at 16, watch ITL.

2. Route by Length

Short requests get their own pool.

3. Prefix Caching

--enable-prefix-caching

Reuse KV for shared prompts. 30-50% memory savings.

4. Scale on Queue

Queue depth = leading indicator.
GPU% = lagging.
Scale when queue > 0 for 3m.

Four mitigations. Cap batch size. Route by length. Prefix caching. Scale on queue, not GPU.
